# Code of conduct

Short, because the rules are simple.

## Expected

- **Critique code, not people.** "This bypasses the capability gate" is useful. "This is amateur
  work" is not.
- **Be precise.** Say what you ran, what you saw, and what you did not verify. An honest gap is
  welcome; a silent one costs trust.
- **Assume competence and good faith.** Contributors here span time zones, languages, and experience
  levels. Ask before concluding someone was careless.
- **Accept a slow review.** Every pull request is read personally by the maintainer. Pinging a
  thread is fine; hostility about the wait is not.

## Not accepted

- Harassment, personal attacks, or demeaning comments about anyone
- Discrimination on any protected characteristic
- Sexualized language or imagery, and unwelcome attention of any kind
- Publishing anyone's private information, including credentials, private paths, or repository names
  found in a log or screenshot
- Deliberately wasting review time: fabricated verification claims, AI-generated pull requests the
  author has not read, or reopening a settled decision without new evidence

This applies in issues, pull requests, commit messages, code comments, and any other project space.

## Enforcement

Report a problem privately through
[GitHub private vulnerability reporting](https://github.com/sarang-sketch/sketch/security/advisories/new),
which reaches the maintainer and nobody else. Include links and, where you can, unedited quotes.

The maintainer decides and acts: a warning, edited or deleted content, a locked thread, or a block
from the repository, proportional to what happened and whether it repeats. Reports are handled
privately. Reporting in good faith never counts against you, even if the outcome is that no action
was warranted.

There is one maintainer, so a response may take days. Serious safety issues come first.
